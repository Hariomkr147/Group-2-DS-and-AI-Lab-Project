# Frontend feature audit

Reviewed the React frontend against the FastAPI backend on `guardrail` at `97914e1c` on 2026-11-18. The sample-pack chat can sign in, ask a question, backtrack to a prerequisite and update progress. The full planned learning journey has release blockers.

## Release blockers

| Priority | Learner impact and evidence | Acceptance check |
|---|---|---|
| P1 | **The first course determines the entire experience.** The UI takes `courses[0]`; the API sorts by ID. With NCERT enabled on a fresh database, Chromium opened `ncert` with zero concept buttons and no way to reach the four-concept `ncert-maths` pack. The NCERT row represents the corpus and has no pack concepts. The UI sends neither grade nor subject. | With both courses present, select either one and see its name. In corpus mode, select class and subject, and show that chapter chat is ungraded. A full chapter/topic browser also needs a catalogue contract. [Tutor startup](../frontend/src/App.jsx) · [Course order](../backend/app/services/course_store.py) · [Corpus seed](../backend/app/main.py) |
| P1 | **The declared deployment enables retrieval without its encoder dependencies.** Render installs `requirements.txt` and enables NCERT. The encoder imports Torch and Transformers, both declared only in the optional RAG dependencies. On a clean deployment using that manifest, an evidence request can reach the encoder-unavailable 503. The automatically selected course consequently depends on a service the build does not provision. | From a clean deployment, ask a scoped corpus question and get a citation to the expected physical PDF page. Verify the sample pack remains selectable if retrieval is unavailable. [Render build](../render.yaml) · [Runtime dependencies](../backend/requirements.txt) · [RAG extra](../backend/pyproject.toml) · [Encoder and error path](../backend/app/services/ncert.py) |
| P1 | **Picking a concept can keep teaching the previous one.** During a Percentages question, clicking Division and sending the suggested text produced `hint / percentages`. The picker writes “I am stuck on …” into the composer. During an active question the backend treats that wording as a help request, while the frontend never sends the supported `new_topic` flag. | Pick Division mid-exercise. The next reply and highlighted concept should both be Division, with no graded attempt on Percentages. [Picker and message payload](../frontend/src/App.jsx) · [Intent handling](../backend/app/services/tutor.py) |
| P1 | **Learners cannot submit the working the tutor requests.** The backend asks for one step per line. Chromium stripped line breaks from a two-line calculation in the single-line input, and Enter submits immediately. The UI also discards the structured `wrong_step` field, which matters on backtrack replies where the reply text can omit it. | Type and paste multiple steps, submit once, and identify the first incorrect line from the reply, including on a prerequisite detour. [Composer](../frontend/src/components/Chat.jsx) · [Grading and feedback](../backend/app/services/tutor.py) |
| P1 | **Diagnostics and standalone practice have no end-to-end path.** Both routes return questions from a course pack. React calls neither. The answer-recording endpoint accepts a client-supplied correctness flag, while the question responses intentionally hide the key. A screen alone cannot grade these exercises reliably. Practice currently selects stored questions by difficulty and count. | Start a diagnostic or a practice set, submit a learner answer for the issued question, have the server grade it, and see progress update once. [Question routes](../backend/app/routers/practice.py) · [Answer contracts](../backend/app/schemas.py) · [Recording](../backend/app/routers/learners.py) |

## Recovery and accuracy

| Priority | Observable behavior | Acceptance check |
|---|---|---|
| P2 | **Refresh abandons the active lesson.** After a wrong answer displayed `0/1 correct`, reload created a different session, displayed zero turns and said “No answers yet”. The backend retains history and progress. React keeps the session ID in component state and first fetches progress after a message. | Reload during a prerequisite detour and resume the same session with the prior transcript, active concept and totals. The history endpoint currently returns role and text only, so restoring per-turn citations or action labels would require backend support. [Startup and progress](../frontend/src/App.jsx) · [Session history](../backend/app/routers/sessions.py) |
| P2 | **A saved turn can look failed.** A simulated 503 on the progress GET after a successful message POST showed the tutor reply followed by “Action not completed”. The server has already committed the turn. A learner who resends can advance the exercise or affect grading again. | Simulate a progress outage after a successful POST. Keep the reply, mark progress temporarily unavailable and retry only the read. For an ambiguous POST failure, reconcile against session history before resubmission. [Send handler](../frontend/src/App.jsx) · [Turn commit](../backend/app/services/tutor.py) |
| P2 | **Transient outages interrupt sign-in and startup.** A simulated 503 on `/auth/me` cleared a valid token and returned to sign-in. A 503 on `/courses` left “Starting…” and a disabled composer with no retry control. Fetch has no application timeout, so a stalled request can also hold the busy state. | Preserve authentication on temporary failures, show a recoverable error and let the learner retry startup. Continue signing out on confirmed expiry. [Bootstrap](../frontend/src/App.jsx) · [HTTP helper](../frontend/src/api.js) |
| P2 | **Citations can outlive the turn they support.** State updates only when the response includes a resource. An uncited redirect or clarification leaves the preceding source visible in the panel. Earlier cited messages have no link of their own. | Follow a cited turn with an uncited turn. Keep the earlier source identifiable with its original message. [Reply handling](../frontend/src/App.jsx) · [Source panel](../frontend/src/components/SidePanel.jsx) |

## Verification

- The production Vite build passed. The backend suite passed all 73 tests against an isolated SQLite database.
- Headless Chromium used the built React assets served by FastAPI, separate temporary databases for sample-pack and NCERT-enabled startup, and local template replies. The sample-pack browser checks also ran at a 390 × 844 viewport with no horizontal overflow on the initial tutor screen. Browser request interception supplied the 503 responses used for the recovery checks.
- Frontend CI currently runs a production build only. A browser regression covering course selection, mid-exercise switching, multiline work, refresh and partial failure would catch the reproduced regressions. [CI workflow](../.github/workflows/ci.yml)
- Live Render, the production pgvector corpus, hosted model quality, and cross-browser accessibility remain unverified. The Render dependency finding comes from the checked-in build configuration.
