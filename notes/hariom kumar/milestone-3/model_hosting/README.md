# Qwen3.5 Socratic Tutor: hosting setup guide

Run [hosting-qwen.ipynb](hosting-qwen.ipynb) in an interactive Colab or Kaggle GPU session to generate a temporary HTTPS API URL and a random API key for the [Socratic Tutor model](https://huggingface.co/IITM-2026T3-DSAI-GROUP2/qwen3.5-4b-socratic-tutor).

The Hugging Face repository contains the final LoRA adapter. The notebook automatically downloads the matching `Qwen/Qwen3.5-4B` base model, tokenizer, and adapter. You do not need to upload adapters, attach training datasets, set local model paths, or run training again. The notebook uses pinned base and adapter revisions for reproducible loading.

## Before you start

- A Google or Kaggle account with access to an NVIDIA GPU runtime.
- A fresh Python 3.11+ session with Internet access.
- A T4 with 16 GB GPU memory is the target configuration; the notebook uses one GPU and loads the model in NF4 4-bit with fp16 compute.
- Access to Hugging Face, PyPI, GitHub, and Cloudflare from the runtime.

No Hugging Face login, Cloudflare account, or manually created endpoint secret is required for the public model. The notebook creates its own endpoint key.

Use this for interactive model testing. GPU availability and session duration depend on the platform and your account. Colab restricts web service offerings unrelated to interactive notebook compute; check its [usage restrictions](https://research.google.com/colaboratory/faq.html#limitations-and-restrictions) before using a managed runtime as an application host. This guide does not promise continuous hosting on either platform.

## Option A: set up on Google Colab

1. Download `hosting-qwen.ipynb` from this folder. A separately supplied copy may be named `hosting-qwen-colab-kaggle.ipynb`; it is the same notebook.
2. Open [Google Colab](https://colab.research.google.com/) and sign in.
3. Choose **File → Upload notebook** and select the downloaded `.ipynb` file.
4. Choose **Runtime → Change runtime type**. Select **T4 GPU**, or another available NVIDIA GPU with sufficient memory, and save.
5. Connect to the runtime. Keep the notebook private while hosting.
6. In the fresh session, choose **Runtime → Run all**.
7. Wait for dependency installation, model downloads, loading, the local generation check, and the public connection checks. The first run may take several minutes.
8. Find the output below **Create your public URL and display the API key**. Copy `API_URL` and `API_KEY` into your application's private configuration.

If you imported model libraries before installing dependencies, restart the runtime and run the notebook again before loading the model. Restart the runtime before repeating the model-loading cell so the previous model does not occupy GPU memory.

## Option B: set up on Kaggle

1. Open [Kaggle Code](https://www.kaggle.com/code), sign in, and create a notebook.
2. Use the notebook's **Import Notebook** option to upload `hosting-qwen.ipynb` or `hosting-qwen-colab-kaggle.ipynb`.
3. In notebook settings, enable an NVIDIA **GPU accelerator** and turn **Internet on**. If GPU T4 x2 is offered, the notebook uses only the first GPU.
4. Keep the notebook private. No input datasets or Kaggle Secrets are needed.
5. Start a fresh **interactive session** and select **Run All**. Do not use a background **Save Version → Save & Run All** run for hosting: the endpoint needs a running session after setup finishes.
6. Wait for the local generation and public connection checks to pass.
7. Copy `API_URL` and `API_KEY` from the public-tunnel cell's output into your application's private configuration.

If GPU or Internet settings are unavailable, follow Kaggle's account requirements shown in its interface. Background server processes do not provide permanent hosting after the notebook session ends.

## Find and use your credentials

Successful setup prints values in this format:

```text
API_URL = https://YOUR-SESSION.trycloudflare.com
API_KEY = YOUR-GENERATED-KEY
PREDICT_URL = https://YOUR-SESSION.trycloudflare.com/predict
```

These are placeholders; use the actual values printed by your run.

- `API_URL` is the base URL. Append `/predict` when requesting a reply.
- `API_KEY` is a random endpoint-only key generated by the notebook. It is not a Hugging Face, Kaggle, or Google account token.
- Send the key as `Authorization: Bearer <API_KEY>` on every request.
- Keep the runtime running while testing. Recreating the tunnel changes the URL; rerunning the local-check cell creates a new key.

The notebook verifies the official Cloudflare client's download digest and checks that the public endpoint accepts the correct key and rejects unauthenticated requests. [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) provide temporary URLs for development and have no uptime guarantee.

## Call the model from Python

Run this client on your computer or in another notebook. Install its only dependency if needed:

```sh
python -m pip install requests
```

Paste the base URL when prompted, then paste the API key into the hidden prompt:

```python
import getpass
import requests

API_URL = input("API_URL: ").strip().rstrip("/")
API_KEY = getpass.getpass("API_KEY: ").strip()
HEADERS = {"Authorization": f"Bearer {API_KEY}"}

TRAINING_SYSTEM_TEMPLATE = (
    "You are a Socratic maths tutor. Guide the student one step at a time "
    "with questions and hints. Never state the final answer.\n\n"
    "Problem: {question}\n"
    "Correct final answer (for checking only, never reveal it): {answer}"
)

messages = [
    {
        "role": "system",
        "content": TRAINING_SYSTEM_TEMPLATE.format(
            question="Solve 2x + 3 = 11.", answer="4"
        ),
    },
    {"role": "user", "content": "I am stuck. What should I do first?"},
]

response = requests.post(
    API_URL + "/predict",
    headers=HEADERS,
    json={"messages": messages, "max_new_tokens": 96},
    timeout=180,
)
response.raise_for_status()
result = response.json()
print(result["text"])
```

Replace the example question and answer with your actual question and a reviewed official answer. Keep the answer and system message on your application's backend. The system instruction guides the model; it does not guarantee that answers will never leak.

For a known first attempt, append `"\n\nStudent's first attempt:\n"` plus the student's attempt to the system message. For follow-up turns, append the model reply as an `assistant` message, then the student's next message as a `user` message. Send the full history each time: the server does not store conversations, and the last message must have role `user`.

## API reference and limits

All routes require the Bearer key. Responses are JSON and do not stream.

| Route | Purpose |
| --- | --- |
| `GET /health` | Returns `{"status": "ok"}` when the local API is running. |
| `GET /metadata` | Returns model revisions, package versions, quantization, and serving limits. |
| `POST /predict` | Returns the tutor reply in `text`, plus token counts, timing, output-limit status, and protocol flags. |

For `/predict`, provide `messages` and optionally `max_new_tokens`, as shown above. Advanced callers can supply an already tokenizer-formatted `prompt` instead of `messages`; do not send both.

| Setting | Limit or behavior |
| --- | --- |
| Output tokens | Integer from 1 to 96; default 96. |
| Context | Input plus requested output must fit within 2,048 tokens. |
| Chat messages | 1–32 entries with `system`, `user`, or `assistant` roles and nonempty text content. |
| Input text | At most 16,000 characters across message contents, or in a raw prompt. |
| Request body | At most 65,536 bytes. |
| Concurrent generation | One request at a time; overlapping generations receive HTTP 429. |
| Decoding | Greedy generation with thinking disabled. |

Oversized inputs are rejected instead of silently truncating the conversation. This is a custom `/predict` API, not an OpenAI-compatible API. Model responses still need correctness and answer-leak checks before being shown to learners. Training dialogues were capped at 768 tokens; longer-context teaching behavior is not established by these hosting checks.

## Stop or restart hosting

To stop, run this in a new notebook cell:

```python
stop_host()
```

You can also disconnect and delete the runtime. **Run All leaves hosting running**; there is no final cell that automatically shuts it down.

To restart hosting while the model is still loaded, rerun the code cell under **Check the model and start the authenticated API**, then the code cell under **Create your public URL and display the API key**. Update your application with the newly printed URL and key. To reload the model itself, restart the runtime and run the notebook from the beginning.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| GPU is unavailable or the notebook asks you to enable one | Select an NVIDIA GPU accelerator and restart the runtime. CPU and TPU runtimes are not supported by this notebook. |
| CUDA out-of-memory error | Restart the runtime to release the previous model, then run once from the beginning with sufficient GPU memory. |
| Import error after installation | Restart the session so it imports the newly installed package versions, then run from the beginning. |
| Hugging Face download fails or is rate-limited | Check Internet access and retry later. An optional read-only `HF_TOKEN` environment variable can help with download rate limits; it is separate from `API_KEY`. |
| No tunnel URL, tunnel exits, or public connection check fails | Inspect `tunnel.log` in the printed working directory. Check Internet and outbound tunnel access, then rerun the local-check and tunnel cells. |
| Browser shows `Unauthorized`, or API returns HTTP 401 | Opening the URL in a browser sends no Bearer key. Use an API client with the current `Authorization` header. |
| HTTP 400, 413, or 415 | Check the request schema, body size, and `Content-Type: application/json`. Use the Python example as a starting point. |
| HTTP 422 | End chat history with a user turn, request at most 96 output tokens, and keep input plus output within the context limit. |
| HTTP 429 | Wait for the current generation to finish before retrying. |
| HTTP 500 or a slow response | Inspect notebook errors. Optional optimized Qwen kernels are not installed; the PyTorch fallback can be slow on a T4. |
| URL stopped working | Check whether the runtime or tunnel ended. Restart hosting and update the application credentials. |

Keep the hosting notebook private. Its output displays the API key, so clear all outputs before saving or sharing a public copy. Keep credentials out of source control, browser-side application code, screenshots, and URLs. Requests travel through Cloudflare; send only data permitted for that processing.
